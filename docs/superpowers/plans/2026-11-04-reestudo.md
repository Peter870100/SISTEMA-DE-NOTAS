# Reestudo ("Estudar este conteúdo") — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** uma explicação escrita com 10 exercícios de fixação por assunto, dentro da etapa "Revisar o conteúdo" do plano
de estudo, publicada automaticamente com quatro travas.

**Architecture:** regras em funções puras em `src/lib/estudos/`, testadas com `tsx --test`; o servidor lê e grava pelo
Supabase; o conteúdo entra só pelo MCP do dono. O aluno lê por `/aluno/estudar/<assuntoId>`, e a correção é sempre no servidor.

**Tech Stack:** Next.js 16.2 (server components + server actions), React 19, TypeScript, Supabase
(`@/lib/supabase/client`), zod, sharp, lucide-react, CSS Modules, `node:test` via `tsx --test`.

**Spec:** `docs/superpowers/specs/2026-11-04-reestudo-design.md`. Leia a spec inteira antes de cada tarefa. Ela traz o SQL,
os textos e as regras. O esboço aprovado é `docs/superpowers/specs/assets/2026-11-04-reestudo/tela-literatura.html`.

## Global Constraints

- **Ambiente:** respostas, textos de tela e mensagens de commit em pt-BR. Trabalhar no worktree `.worktrees/reestudo`
  (branch `reestudo`). Nunca `git stash` sem tag. Next.js 16 tem mudanças: leia `node_modules/next/dist/docs/` antes de usar
  uma API do Next que você não viu no código do projeto (por exemplo, `params` é uma Promise).
- **Server actions:** nunca lançam para o cliente; devolvem `{ ok: true, ... } | { ok: false, erro: string }`. A conta vem
  sempre da sessão, nunca de parâmetro.
- **Acesso:** toda leitura do aluno passa por `estudoParaTela`. Gabarito e comentário de exercício não respondido nunca saem
  do servidor.
- **HTML:** nenhum `dangerouslySetInnerHTML`. Texto do banco passa pelo React como texto.
- **Imagem:** desenho só por `<img src="data:image/svg+xml;base64,...">`, com `alt`. Foto só com `aprovada_em` preenchido.
- **Sem custo de API:** nada aqui chama a API do Claude.
- **Visual:** padrão do skill `status-visual-aluno` (invoque-o nas tarefas de tela). Sem texto cinza. Funciona em 1340px, 390px
  e 320px, sem rolagem horizontal.
- **Testes:** todo `*.test.ts` novo entra no script `test` do `package.json`, no fim da lista.
- **Verificação:** `npm test` e `npm run lint` no fim de cada tarefa que muda código; `npm run build` nas tarefas de tela e na final.
- **Commits:** terminam com a linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Exercício tirado do ar com a página aberta:** quem responder depois vê uma mensagem clara, sem quebrar a tela; se todos
  saírem, aparece "Nenhum exercício disponível agora" (Task 4 e Task 6).
- **Foto ainda não aprovada ou recusada:** o bloco `imagem` some e o `trecho` aparece sem foto, sem imagem quebrada (Task 6,
  `blocosVisiveis`).
- **Duas abas respondendo o mesmo exercício com letras diferentes:** vale a primeira, e as duas mostram a mesma correção
  (Task 4).
- **Texto do banco com `<script>` ou `<b>`:** aparece como texto, sem executar (Task 6, `Blocos` usa o markdown mínimo).
- **Tabela larga ou trecho longo no celular:** a tabela rola dentro do cartão, e a página não ganha rolagem horizontal
  (Task 6, conferir em 320px).
